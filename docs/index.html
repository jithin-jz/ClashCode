Overview

ClashCode is a gamified coding platform where developers solve programming challenges, earn XP, level up, and connect with other coders in real-time. Built as a distributed microservices system on AWS EKS.

🎮

Gamified Learning

60 progressive Python levels, XP economy, star ratings (0-3), achievements, badges, certificates, and a cosmetic marketplace.

💬

Real-Time Chat

WebSocket messaging with presence tracking, reactions, message editing/deletion, search, and DynamoDB-backed history.

🤖

Agentic AI Mentor

A LangGraph agent that runs learner code in the sandbox and searches a Pinecone knowledge base (agentic RAG) to give adaptive, leak-safe hints grounded in real test failures — plus automated code reviews.

⚡

Secure Execution

AST-validated code runs in read-only, network-disabled Docker containers with strict CPU/memory/PID limits.

📊

Analytics & Admin

Full admin dashboard with user management, audit logs, store CRUD, Celery task monitoring, and system health.

🛒

Economy & Payments

XP-based store (themes, fonts, effects, victory animations), daily check-in streaks, referrals, and Razorpay integration.

AI Service FastAPI — Port 8002

Agentic tutoring engine. A LangGraph agent orchestrates tool-calling over the executor sandbox and a Pinecone knowledge base (agentic RAG), backed by Groq (Llama 3.3 70B) via LangChain.

Agentic Tutor (LangGraph)

A reason-act state graph (agent → tools → agent, bounded loop) that decides which tools to call before answering:

  1. run_challenge_tests — executes the learner's code against the hidden tests in the sandboxed executor, so hints are grounded in the real failure, not a guess
  2. search_similar_challenges — agentic RAG: Pinecone semantic search, invoked only when conceptual context helps
  3. Agent synthesizes one adaptive, level-calibrated hint; a sanitizer + system prompt prevent full-solution leakage
  4. The tool trace (e.g. run_challenge_tests) is returned so the UI can surface a "Ran your code" indicator

Classic RAG Pipeline (fallback / analysis)

  1. Challenge description + user code combined as query
  2. Pinecone similarity search (k=2) using native embeddings
  3. Filter out same-challenge results (by slug)
  4. Context injected into the LLM prompt for hint/review generation

Mode is toggled by the Core worker via the AI_HINT_MODE env flag (agent → /hints/agent, otherwise the classic /hints chain).

Key Components

  • core/agent.py — LangGraph reason-act agent (state graph, bounded loop, tool trace)
  • core/agent_tools.py — per-request tools: sandboxed test runner + RAG search
  • utils/executor_client.py — HMAC-signed client to the executor sandbox

Security Layers

AST Validation (Pre-execution)

Blocked modules: os, subprocess, socket, shutil, pathlib, ctypes, multiprocessing, threading, asyncio, http, urllib, requests, ftplib, telnetlib, ssl, sys, platform

Blocked functions: eval, exec, compile, open, getattr, setattr, delattr, globals, locals, vars, breakpoint

Blocked attrs: __subclasses__, __globals__, __builtins__, __mro__, __import__

Container Constraints

  • • Read-only filesystem
  • • Non-root user (10001:10001)
  • • All Linux capabilities dropped
  • • no-new-privileges flag
  • • PID limit: 128
  • • Memory: 256MB container / 128MB per execution
  • • CPU: 1.0 core
  • • Timeout: 5 seconds
  • • Max code size: 64KB
  • • Max output: 32KB
  • • tmpfs /tmp: 64MB, noexec

Databases

PG

PostgreSQL 15

Primary

Relational data with SSL, connection pooling. Stores users, profiles, challenges, submissions, XP transactions, posts, payments, certificates, achievements, store items, notifications.

Config: dj-database-url, cache prefix "coc", 5min cache timeout. Test mode uses SQLite.

RD

Redis 7

Cache + Broker

Sessions, rate limiting, OTP codes, leaderboard cache, Celery task broker/results, chat pub/sub broadcasting.

AOF persistence, password-protected, DB1 for Django cache.

DD

Amazon DynamoDB

NoSQL

Two tables: ChatMessages (room_id + timestamp) and UserActivity (user_id + date). Handles chat persistence with automatic table creation.

Local dev: amazon/dynamodb-local Docker image. Prod: AWS managed with IRSA auth.

PC

Pinecone

Vector DB

Stores embeddings for challenge descriptions and hint templates via LangChain Pinecone integration. Native embeddings model. Enables semantic similarity search (k=2) for the RAG pipeline.

Security

Authentication & Authorization

  • • JWT tokens: RS256 primary with HS256 fallback, 1hr access / 7-day refresh
  • • Refresh tokens stored in HttpOnly secure cookies
  • • OAuth 2.0: GitHub + Google with frontend callback URIs
  • • Email OTP verification for sensitive operations
  • • Rate-limited login/OTP endpoints
  • • SecurityAuditLog tracks all auth events (user, IP, user-agent, action)
  • • Passwords hashed with bcrypt

Code Execution Isolation

  • • Layer 1: AST-based static analysis blocks 18+ dangerous modules and 12+ dangerous functions
  • • Layer 2: Blocks dunder attribute access (__subclasses__, __globals__, __builtins__, __mro__)
  • • Layer 3: Docker container — read-only fs, no network, non-root, all capabilities dropped
  • • Layer 4: Resource limits — 5s timeout, 128MB RAM, 1 CPU, 128 PIDs, 64KB input, 32KB output
  • • Containers destroyed immediately after execution

Network & Infrastructure

  • • Nginx: server_tokens off, X-Content-Type-Options nosniff, X-Frame-Options DENY, strict Referrer-Policy, Permissions-Policy blocks camera/mic/geo
  • • Databases in private subnets (no internet access)
  • • IRSA (IAM Roles for Service Accounts) — least-privilege per pod
  • • Secrets via external-secrets.io synced from AWS Secrets Manager
  • • Service-to-service calls signed with HMAC (INTERNAL_SIGNING_SECRET)
  • • Django: HSTS, SSL redirect, CSRF protection, secure cookies
  • • Trivy vulnerability scanning on every Docker image push

Local Setup

Get the project running locally for development.

Docker Node.js 18+ Python 3.11+ Git

1. Clone & configure

git clone https://github.com/jithin-jz/clashcode.git
cd clashcode
# Copy .env.example → .env in: services/, services/core/, services/chat/, services/ai/, frontend/

2. Start backend (all services + databases)

cd services
docker compose up -d --build

This starts: nginx, postgres, redis, dynamodb-local, core, chat, ai, executor, celery worker, celery beat, flower

3. Initialize database & content

docker compose exec core python manage.py migrate
docker compose exec core python manage.py createsuperuser
docker compose exec core python manage.py load_levels
docker compose exec core python manage.py seed_store
docker compose exec core python manage.py seed_achievements

4. Start frontend

cd frontend
npm install
npm run dev   # → http://localhost:5173

Troubleshooting

  • • Port 80 busy → change NGINX_HTTP_PORT in services/.env
  • • Can't login → check db container: docker compose ps
  • • Chat not persisting → verify DynamoDB container is running
